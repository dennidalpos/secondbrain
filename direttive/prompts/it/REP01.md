# REP01 — Completa il prossimo task pronto del repository aperto

> **Scope**: repo | **Modalità**: scrittura | **Cosa serve**: task pianificato e criteri di accettazione | **Esempio d'uso**: `esegui il prossimo task prioritario che si può fare in autonomia`

## Scopo

Portare a termine una voce concreta del backlog autorevole (issue tracker, file di task o board). Per trovare lavoro non tracciato nel codice usa REP08.

## Quando usarlo

Quando si chiede di far avanzare un lavoro già registrato.

## Input

Il repository aperto e la sua fonte di backlog; eventuali preferenze su quale task scegliere.

## Attività specifiche

Valuta priorità, dipendenze, stato e i criteri reali senza presumere uno schema. Scegli un task pronto del repository corrente, implementalo e verifica il risultato. Rifiuta i task che appartengono ad altri repository, anche se marcati come autonomi: il perimetro è il repository in uso e gli aggiornamenti del backlog restano lì.

## Verifiche

Chiudi solo i criteri provati; mantieni le voci parziali e bloccate con il motivo. Una voce del backlog non è un'autorizzazione indipendente dalla richiesta dell'utente.

## Consegna

Il task scelto, il risultato, le evidenze e l'aggiornamento del backlog secondo il suo schema e la sua storia; il motivo se nessun task è pronto.

## Prompt vicini

- DEV01: Implementa una funzionalità con i controlli pertinenti.
- PRG04: Prepara un piano a fasi con dipendenze e controlli.
- REP08: Ispeziona il repo e trova i task residui rispetto al codice reale.
