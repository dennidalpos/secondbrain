## Integrazione SecondBrain della postazione

<!-- secondbrain:tracker-contract:1 -->

- Risolvi SECONDBRAIN_HOME dall’ambiente utente del sistema; il valore è locale e non va copiato nelle istruzioni account o nei repository pubblici. Il bootstrap dal checkout SecondBrain funziona anche senza variabile o configurazione. Configurazione e output operativi sono sotto .runtime del clone.
- I dossier condivisi contengono index.md, context.md, memory.md, repository.json e tracker dichiarato. Para-index.json risolve gli identificatori; archivi e conflitti richiedono gestione esplicita.
- Attivazione: sb attiva (SYS03). Discovery in lettura dei volumi locali accessibili, mappa di repository/checkout/IDE/profili e conferma effettiva dell’utente prima dell’attivazione. Rete, rimovibili, WSL, VM e container richiedono selezione esplicita. I nuovi asset non diventano gestiti automaticamente; non esistono monitor periodici.
- Controllo: sb controlla (SYS04) verifica senza correggere. Sb allinea applica testi già approvati agli asset gestiti, preserva conflitti e propone asset nuovi. La compattazione usa SYS05 e originali conservati; sb compatta richiede il dossier da trattare.
- CLI relativa alla radice SecondBrain: scripts/secondbrain.ps1 -Discover; -Activate -SelectionPath con anteprima e -Apply dopo conferma; -Check e -Sync per gli asset approvati. Il contesto iniziale si carica con scripts/knowledge.ps1 -Startup o -Tasks (o lo strumento MCP get_startup_context): profilo snello entro 30.000 caratteri solo per il primo caricamento (predefinito) o -Profile Full; -Search ha un tetto predefinito (-Budget e -Limit per ampliarlo, -AllDossiers per tutti i dossier); -Report misura caratteri e peso delle direttive. Scripts/prompts.ps1 -Context -RepositoryPath risolve soltanto i percorsi del dossier. Scripts/trace.ps1 -InstallHook (anteprima, poi -Apply) installa l’hook Stop di Claude Code che alimenta l’avviso di compattazione di -Check. ConfigPath è un override esplicito.
- Lettura iniziale dai file senza sessioni Hold. Per scritture prolungate usa scripts/access.ps1 con Start/End nello stesso script e try/finally; passa SessionId alle CLI. Non forzare lock o cancellare marker di transazioni incomplete.
- Fonte tracker: repository.json con tracker location=dossier, path=tracker.json, schemaVersion=1 richiede esclusivamente quella fonte; assenza o invalidità dichiarata sono errori senza fallback. Le importazioni preservano originali, task e riferimenti; candidato e fonte attiva restano distinti.
- Direttive IDE: SYS01 distingue file locale, installazione, profilo, ambiente e account. Registra alias locali e prove osservate; file allineato non dimostra caricamento. Allineamento account assistito entro autorizzazioni e strumenti disponibili; nessuna verifica inventata o automazione del login.
- Prompt: sb prompt senza argomenti esegue scripts/prompts.ps1 (o lo strumento MCP get_prompt_home) e riporta integralmente link al catalogo, tabella dei comandi sb, primi passi e guide per il primo avvio, senza riassumerli e senza eseguire alcun primo passo che scriva file dell'utente se non richiesto. Sb prompt list (alias tutti) riporta l'elenco compatto integrale dei prompt generici (prompts.ps1 -List -Compact o list_prompts con compact) e sb prompt maintenance quello dei prompt di manutenzione di SecondBrain (-Pack maintenance), una riga per prompt, mai troncato né riassunto. Sb prompt ambito AREA, sb prompt mostra CHIAVE e sb prompt CHIAVE risolvono per ID immutabile (pmt-…), codice o alias allo stesso prompt; carica soltanto la scheda necessaria.
- Scheda prompt uniforme in ogni IDE e canale (CLI, MCP, composizione): ID e codice, Titolo, Cosa fa, Esempio d'uso, Modalità (lettura, scrittura o verifica), Ambito (repository, area, file/funzione), Cosa serve e Regola vincolante. Il prompt composto segue CO-STAR (Context, Objective, Style, Tone, Audience, Response). Regola vincolante: in caso di dubbio fermati, non procedere per ipotesi e chiedi con Function Calling / Tool Use a scelta multipla (es. ask_question).
- Dopo modifiche pertinenti ai dossier usa Sync e Check. Per i blocchi gestiti modifica i generatori; non modificare snapshot o blocchi a mano. Le nuove prescrizioni comuni richiedono proposta concreta, approvazione esplicita e hash verificati prima della distribuzione.
